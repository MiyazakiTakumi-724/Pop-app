# Pop 仕様書

最終更新：2026-10-08

## 1. 概要
食べ物・商品などのレビューを気軽に投稿できる匿名投稿サイト。投稿（＝**ポップ**）は掲示板形式で新着順に並ぶ。
自分たちの練習用。スマホで見ることを想定する。

## 2. 機能
**やること（MVP）**
- ポップの投稿（タイトル・タグ・住所・本文・画像）
- 掲示板での一覧表示（簡易表示）と、タグによる絞り込み
- ポップの詳細表示

**やらないこと**：コメント、通報・モデレーション、キーワード検索、ログイン（匿名のため不要）

## 3. 画面
| 画面 | 内容 |
|---|---|
| 掲示板（一覧） | ポップをカードで新着順に並べる。上部でタグを入力して絞り込む |
| ポップ詳細 | カードを押すと開く |
| 投稿フォーム | 新規投稿。並び順：タイトル（必須）→ タグ → 住所 → 本文 → 画像（必須） |

遷移：一覧 →（カード）→ 詳細　／　一覧 →（投稿ボタン）→ 投稿フォーム →（投稿完了）→ 一覧
詳細の開き方（別ページ／モーダル）は未決定。モックは画面切り替え方式。

**タグの操作**
- **一覧**：入力欄にタグを入力し、「追加」かEnterで絞り込み条件に加える。複数追加でき、**すべてのタグが付いたポップだけ**を表示（完全一致）。×で外し、「すべて解除」で全件に戻す
- **カード・詳細**：タグは表示のみ（押しても絞り込まない）。カードは先頭3個まで、残りは「+2」のように数で表す
- **投稿フォーム**：入力して追加、×で外す。よく使われているタグを候補として出し、タップで追加できる（表記ゆれを減らすため）
- **表記ルール**（フロント・バック共通）：前後の空白と先頭の「#」を除く／空は無視／重複は1つにまとめる

## 4. 見た目の共通ルール（CSS）
色・文字・余白は直書きせず、**必ず下の変数（`var(--名前)`）を使う**。変えるときは二人で相談する。
配色は**オレンジがメイン**で、水色は補助、白はカードなどの面。どれも彩度を抑えたやさしい色にする。

`css/style.css` の先頭に次をそのまま置く。

```css
:root {
  --color-primary: #F6D8C4;        /* ヘッダー・主なボタンの背景 */
  --color-primary-hover: #F0C8AA;  /* ボタンを押している間・ボタンの枠線 */
  --color-primary-text: #9A5A3B;   /* オレンジ色の文字・リンク */
  --color-bg: #FFFCF9;             /* ページの背景 */
  --color-border: #F5E6DA;         /* 枠線・区切り線 */
  --color-surface: #FFFFFF;        /* カード・入力欄 */
  --color-tag-bg: #EEF5F9;         /* タグの背景（水色） */
  --color-tag-text: #4A6A80;       /* タグの文字 */
  --color-accent: #5A97BF;         /* 入力欄を選択中の枠（水色） */
  --color-text: #4A4643;           /* 本文・タイトル */
  --color-text-sub: #6B655F;       /* 投稿日時などの補助の文字 */

  --font-xs: 12px;                 /* タグ・投稿日時 */
  --font-sm: 14px;                 /* 補助の文字 */
  --font-base: 16px;               /* 本文・ボタン・入力欄 */
  --font-lg: 18px;                 /* カードのタイトル */
  --font-xl: 24px;                 /* 画面の見出し */

  --space-1: 4px;                  /* 余白はこの4種類だけ */
  --space-2: 8px;
  --space-3: 16px;
  --space-4: 24px;

  --radius-md: 8px;                /* ボタン・入力欄 */
  --radius-lg: 12px;               /* カード */
  --radius-pill: 999px;            /* タグ */
}
```

**守ること**
- 水色は**タグと、入力欄を選択中の枠だけ**に使う
- オレンジの上の文字は**白にしない**（`--color-text`を使う）。オレンジを文字の色にしたいときは`--color-primary-text`を使う
- ボタンには`--color-primary-hover`の1pxの枠線を付ける（背景が淡く、白に溶けやすいため）
- スマホ幅が基準：中身は最大幅480px・中央寄せ・左右余白16px
- 押せるものは高さ44px以上。入力欄の文字は16px以上（それ未満だとiPhoneで入力時に画面が拡大される）

## 5. データ項目と入力の制限
| 項目 | 一覧 | 詳細 | 入力の制限 |
|---|---|---|---|
| タイトル | ○ | ○ | 必須・1〜50文字 |
| 画像 | 1枚目のみ | 全て | 必須・1〜4枚、1枚5MBまで、JPEG / PNG / WebP |
| タグ | 先頭3個 | 全て | 任意・個数の制限なし・1つ20文字まで |
| 本文 | × | ○ | 任意・2000文字まで |
| 住所 | × | ○ | 任意・200文字まで |
| 投稿日時 | ○ | ○ | 自動 |

- 匿名のため、投稿者を識別する情報は持たない
- 通報機能がなく、個人宅の住所が書き込まれても止められない。住所欄に「お店や施設の住所を入力してください」と案内を出す

- DB設計・サーバー構成・バックエンドの実装方針はitoに一任する

## 7. 技術スタックと開発環境
- **フロント**：HTML / CSS / JavaScriptのみ（フレームワーク・ビルドツールなし）。Fetch API・FormDataを使う
- **バックエンド**：Java + Spring Boot（JDKとMaven/Gradleが必要。ito側のみ）
- **DB**：PostgreSQL（Renderのディスクは永続しないため、SQLiteは使えない）
- **画像**：Cloudinary等の外部ストレージに保存し、URLをDBに記録する（サーバーのディスクに置くと再デプロイで消える）
- **確認**：VS Code + Live Server（`http://127.0.0.1:5500`）。`file://`で開くと`fetch`がブロックされるので使わない。開発中はフロント（5500番）とバック（8080番）が別オリジンのため、バック側でCORSを許可する

## 8. リポジトリ構成
フロントとバックは同一リポジトリ。Spring Bootは`static/`のファイルをそのまま公開するので、フロントをここに置けばJavaサーバーが配信してくれる。

```
Pop-app/
├── server/                          … Spring Boot
│   ├── pom.xml
│   └── src/main/
│       ├── java/...                     … バックエンド一式（ito）
│       └── resources/
│           ├── application.properties   … DB接続設定など（ito）
│           └── static/                  … フロントエンド
│               ├── index.html               … 一覧画面（takumi）
│               ├── post.html                … 投稿フォームの画面（takumi）
│               ├── js/
│               │   ├── api.js / common.js       … 共通JS（takumi）
│               │   ├── list.js                  … 一覧・詳細画面（takumi）
│               │   ├── post.js                  … 投稿フォームの画面の操作（takumi）
│               │   └── post-submit.js           … 投稿フォームの送信処理（ito）
│               └── css/
│                   ├── style.css                … 共通部品だけ
│                   ├── list.css                 … 一覧・詳細専用
│                   └── post.css                 … 投稿フォーム専用
├── mockup/                          … 画面構成確認用のワイヤーフレーム
└── docs/                            … 仕様書・API仕様
```

詳細画面のファイルは、開き方が決まり次第追加する。

## 9. デプロイ
Renderに1サービスで置く。Spring Bootが、APIとフロント（HTML/CSS/JS）の両方を返す。本番は同一オリジンなのでCORSは不要。
DBはRenderのPostgreSQL、画像はCloudinary。JavaはRenderがネイティブ対応しておらず、`Dockerfile`が必要になる見込み。

## 10. 開発の進め方
- フロントとバックは並行開発。API仕様（[api.md](api.md)）を先に合意し、フロントはダミーデータで進める
- Issueは使わない。担当は6章に従い、何をやるかは二人で口頭・チャットで合わせる
- `feature/xxx`ブランチで作業し、**Pull Requestでお互いにレビューしてからmainへマージ**する（mainへ直接pushしない）
- PRの説明には、**何をしたか**と**どう確認したか**を書く（PRが作業の記録になる）
- `main`は常に動く状態を保つ

**作業の順番**
- **takumi**：①雛形を`static/`へ移動（済） → ②各画面の骨組み（HTMLとJS。見た目は後回し。一覧 → 詳細 → 投稿フォームの順。共通JSは、各画面と一緒に必要な分だけ作る） → ③CSS
- **ito**：①Spring Bootの土台（CORS・アップロード上限・エラー応答）とDB → ②API（一覧・詳細・タグ） → ③画像アップロード（Cloudinary）と投稿API → ④投稿フォームの送信処理
- **二人で**：フロントとバックを繋いで動作確認 → デプロイ

**取り決め**
- **雛形の移動**：takumiが最初のPRで、ルートの`index.html` `css/` `js/`を`server/src/main/resources/static/`へ`git mv`で移す。itoは土台を作るとき`static/`を上書き・削除しない
- **CSS**：各ページの骨組みができてから書く。それまでもHTMLには共通部品のクラス名（`header` `container` `logo` `btn` `btn-block` `input` `card` `tag` `text-sub` `link`）を付けておく。共通部品は`style.css`だけ、画面専用は`list.css` `post.css`など別ファイル（同じファイルを二人が編集してぶつからないため）
- **共通JS**：API呼び出しと整形は`js/api.js` `js/common.js`にまとめる（takumi）。最初から全部は作らず、各画面と一緒に必要な分だけ作る。`USE_MOCK`がtrueの間は、api.mdのレスポンス例と同じ形のダミーデータで動く。タグの整形（`normalizeTag`）はここの1つを使う
- **共通JSの受け渡し**：itoの送信処理が使う`createPop` `getTags` `normalizeTag`は、itoがその作業に入るまでにmainに入れる（takumi）
- **ユーザーが入力した文字の表示**：`textContent`を使い、`innerHTML`に入れない（匿名で誰でも書き込めるため）
- **秘密情報**：DBのパスワード、Cloudinaryのキーなどはコミットしない。環境変数で渡し、READMEには変数名だけを書く
- **API仕様の変更**：PRで出し、二人で合意してから実装を直す
